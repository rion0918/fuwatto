# ADR 0007: 期限切れの表示を分離し自動整理の確認内容を端末内に保持する

Date: 2026-11-16

## Status

Proposed

後続の検討: [ADR 0008](0008-retain-past-reminders.md)で、自動削除の選択を廃止し保存へ統一する変更を記録。

## Context

期限切れを残す設定では、ホームとWidgetにこれからの予定と同じ表示で混在する。自動整理を有効にすると、起動時に削除されるため、何がなくなったかを確認できない。Widgetはアプリと別の接続でSQLiteを読み、アプリを閉じている間も期限切れを非表示にする。

## Decision

ホームの浮かぶ泡とWidgetの予定欄は、これからの予定だけを表示する。残した期限切れは「過ぎた予定」の件数と入口にまとめ、既存の一覧・編集・削除へつなぐ。予定の時刻を過ぎたことと、用事が完了したことは区別する。

自動整理では、タイトル・予定日時・終日区分・元のIDを一時的な確認用テーブルに保存してからリマインダーを削除する。この2操作は同じSQLiteトランザクションで行う。確認内容はPortを介して取得し、ホームに「空へかえった泡」として案内する。明示的に確認したIDだけを削除し、再起動やバックグラウンド復帰で未確認内容を失わない。手動削除は記録しない。サーバーには送らない。

検討した他案:

- 同じ泡の色だけを変える: 混在と場所の取り合いが残るため採用しない。
- 整理件数をメモリにだけ保持する: 起動前の削除や再起動でタイトルを確認できないため採用しない。
- 削除済みリマインダーを永久に保持する: 自動整理の意図に反するため、確認までの最小限の内容だけを保持する。

## Consequences

- 利点: これからの予定を優先し、残した予定は別の場所で見返せる。
- 利点: アプリを閉じている間に泡がなくなっても、次のホームで内容を確認できる。
- 利点: 確認中に別の予定が整理されても、その未確認内容を誤って消さない。
- 受け入れる欠点: 確認するまでは整理済みのタイトルと日時が端末内に一時的に残る。設定画面でもこの保持期間を説明する。
- 受け入れる欠点: Widgetは操作・サイズの制約があるため、過ぎた予定の詳細はアプリで開く。

確認方法: SQLiteの保存・削除の原子性と再接続、確認済みIDだけの削除、Widgetのサイズ別配置、ホームとWidgetの入口、両設定でのAndroid Development Build操作を検証する。
