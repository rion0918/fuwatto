# ADR 0006: 「傾けてこえメモ」の初回オンボーディング完了フラグを分離し同意モーダル後に全画面練習導線を提示する

Date: 2026-11-15

## Status

Proposed

## Context

これまで「左右に傾けて音声入力」機能は初期状態で OFF であり、利用者は設定画面からスイッチを有効化して初めて案内・傾き練習モーダルに到達する設計だった。そのため、アプリの代表的な入力導線である「傾けてこえメモ」を初回起動時に発見しづらく、一方で初回から同意・権限要求・実音声録音をまとめて求めると拒否や誤動作につながる懸念があった。

以下の制約を満たしながら初回体験を設計する必要があった。

1. 新規インストールユーザーには初回起動で価値と操作イメージを伝え、「オンにして試す」「オフのままはじめる」をすぐ選べるようにする。
2. 既存ユーザーのアップデートでは、これまでどおり意図しないオンボーディングモーダルを再表示せず、設定画面からの再試行導線（`raiseToSpeakIntroSeen`）だけを維持する。
3. `AnalyticsConsentGate` が未回答（`unknown`）の環境では利用状況同意モーダルとオンボーディングモーダルが同時に重ならないようにし、ディープリンクやホーム画面の傾き音声入力を完了まで待機させる。
4. 既存の保護ルールに従い、専用 migration パッケージは導入せず、`src/db/schema.ts`・`src/db/migrations.ts` の互換初期化契約で完結させる。

## Decision

1. **完了フラグの分離（`raise_to_speak_onboarding_completed`）**:
   - `app_settings` テーブルおよび `AppSettings` ドメインモデルに `raiseToSpeakOnboardingCompleted: boolean` を追加し、設定画面向けの導入済み判定（`raiseToSpeakIntroSeen`）と初回オンボーディングの完了判定を分離する。
   - SQLite v8 マイグレーションでは、新規 DB の初期値を `0`（未完了）、既存 DB（v1〜v7 相当の既存テーブルまたは既存バージョンあり）の移行値を `1`（完了済み）とし、既存ユーザーには初回オンボーディングを表示しない。
2. **表示順とホーム機能のゲーティング**:
   - `analytics.configured && analyticsConsent === 'unknown'` の間は `AnalyticsConsentGate` を優先し、非同意（`denied`）も含めて同意判定後に「傾けてこえメモ」オンボーディングを表示する。`!analytics.configured` の場合は直接オンボーディングへ進む。
   - オンボーディング表示中および「準備できました」完了画面の表示中は、ホーム画面での傾き音声入力起動をブロックし、Widget の `action=add` / `action=view` ディープリンクもオンボーディング終了まで保留する。
3. **既存 `RaiseToSpeakIntroModal` への `mode="onboarding"` 統合**:
   - 新規ライブラリ追加を避け、`RaiseToSpeakIntroModal` に全画面ラベンダーテーマの `mode="onboarding"` を拡張した（既存 `mode="modal"` の設定導線は従来どおり維持）。
   - 導入画面では約4秒のアニメーションデモ（「動きをもう一度見る」で再生可能、`Reduce Motion` 時は静的表示）と保存されないデモである旨の明記を行い、練習中は発話不要の安心案内・バックグラウンド遷移時の `awaiting-tilt` リセット・恒久権限拒否時の OS 設定導線・完了時の手動「はじめる」ボタンを提供する。

検討した他案と見送り理由:

- **案A: `raiseToSpeakIntroSeen` を流用して初回オンボーディング完了も管理する案**
  - スキップ時に「初回完了済みだが未練習（設定 ON 時に再度練習が必要）」な状態を表現できなくなるため見送った。
- **案B: 別ルート画面（Expo Router ページ遷移）としてオンボーディングを実装する案**
  - 初回ディープリンク保留や `AnalyticsConsentGate` との重なり制御が画面遷移状態に分散し、練習キャンセル・完了直後の戻る挙動でホーム復帰が不安定になるため、ホーム上で完結するモーダルモード拡張を採用した。

## Consequences

- 利点:
  - 新規ユーザーだけに迷いの少ない初回オンボーディング（デモ → 声なしの傾き練習 → 手動完了）を届けつつ、既存ユーザーの挙動を壊さない。
  - 設定画面側の `mode="modal"` 導線および既存のセンサー・音声認識設定との一貫性を保てる。
- 受け入れる欠点:
  - `HomeScreen` 側にオンボーディングセッション状態とディープリンク保留の制御が増えるため、`HomeScreen.ui.spec.tsx` および実機 QA チェックリストでの継続確認が必要になる。
- 確認方法: `pnpm run mvh:verify` および [Development Build QA チェックリスト](../QA_DEVELOPMENT_BUILD.md) の初回オンボーディング項目で検証する。
