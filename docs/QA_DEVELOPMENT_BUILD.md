# Development Build QA チェックリスト

## 概要

EAS Build による development build（`.ipa` / `.apk`）を実機にインストールし、「ふわっと。」MVP の動作を確認するためのチェックリストです。

## テスト環境

| 項目           | 内容                                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| ビルド種別     | development build（`developmentClient: true`）                                                                                              |
| 配布方法       | internal distribution（`.ipa` / `.apk`）                                                                                                    |
| 対象 OS        | iOS / Android                                                                                                                               |
| 前提条件       | 通知権限のリクエスト、日本語 IME、SQLite、Expo Notifications が実機ネイティブ環境で動作することを確認                                       |
| リリース方針   | Android を先行し、App Store は Android 専用 Widget を除く共通機能を後追いで確認する。Android Widget は初回Androidリリース機能として確認する |
| バージョン管理 | ユーザー向けは `expo.version`、Android提出番号は `android.versionCode`、iOS提出番号は `ios.buildNumber` を更新する                          |

## 2026-11-17 保存方針の統一と1行入口の確認

- Android 15 Development Buildの専用QA端末で、未来3件と過去3件を使って確認した。
- 旧自動消滅ONのデータでも過去の予定を保持し、コールド起動後も1行の入口に件数が表示される。
- 入口から過去の一覧を開ける。枠・背景・説明文がなく、追加・凡例と重ならない。0件のホームも確認した。
- 設定の自動消滅と「泡と音声入力」の見出しがなく、左右に傾けて音声入力のスイッチと説明図を維持する。
- 約343dp幅・文字サイズ1.3倍でも入口は欠けない。既存の泡内タイトルにはこの条件で文字欠けが残る。
- Widgetの新条件は実SQLiteテストで確認。今回のWidget実機描画・iOS・TalkBackは未実施。
- 画像比較と制約はリポジトリ直下の `design-qa.md` に記録した。

## 2026-11-16 期限切れ表示の検証記録（当時の自動整理案）

この節は旧案の検証履歴。現在の保存方針は下記チェック項目とADR 0008を参照。

Android 15 の専用エミュレータで、Development Build と今回の Metro バンドルを使用。検証用データのみで確認した。

- 保持する設定: ホームの泡とWidgetの予定欄は未来の3件だけを表示し、「過ぎた予定 1件」から専用一覧へ移動できる。
- 過ぎた予定を未来へ編集すると、一覧の件数が減り、ホームの泡とWidgetの予定欄へ戻る。
- 過ぎた予定しかない場合: ホームは追加用の泡と過去一覧の入口を表示し、Widgetは「これからの予定はありません」と過去件数を表示する。
- 自動整理を有効にすると、4件のタイトル・日時を「空へかえった泡」で確認できる。閉じて再起動しても4件を保持する。
- 「確認しました」で確認内容を削除し、再起動後に同じ案内を表示しない。SQLiteでもリマインダー0件・確認内容0件を確認した。
- アプリを閉じている間に期限を過ぎた別の予定も、次回起動したホームで案内される。
- 幅約343dp・文字サイズ1.3倍・アニメーション無効でも、長いタイトルを全文表示し、シートを広げて確認ボタンまで操作できる。
- Widgetの4列・3列表示で、過去一覧と追加の入口が重ならず表示される。最小250×180などの配置は自動テストで検証した。

起動時に未表示の案内シートへ `dismiss()` を送ると初回に開けない問題を検出し、表示済みの場合だけ閉じるよう修正した。回帰テストとコールドスタートで確認済み。

未実施: Android実機のTalkBack、メーカー別ランチャー、iOS実機。既存の通知配信・購入・ストア提出の全項目を合格とする記録ではない。

## 環境別のDevelopment Build起動手順

このプロジェクトは `expo-dev-client` を含むため、普段は `pnpm run dev` でMetroを起動し、インストール済みのDevelopment Buildから接続します。QRのURLが `exp+pop-reminder://expo-development-client/...` の場合、そのQRはExpo GoではなくDevelopment Buildアプリで開きます。

1. Nix 開発シェルに入る（direnv を使っている場合は `cd` するだけで自動適用）。

```bash
# direnv が有効な場合は自動。手動の場合:
nix develop
pnpm install
```

2. 対象OS・端末に応じてDevelopment Buildを用意する。

### Androidエミュレータ

エミュレータを起動した状態で実行します。起動中の `emulator-*` を自動判定します。

```bash
pnpm run dev:android:emulator
```

複数のエミュレータが起動している場合は、候補に表示されたIDを指定します。

```bash
pnpm run dev:android:emulator -- emulator-5554
```

### Android実機

USBまたはADB経由のインストールが制限されている端末では、EASでAPKを作成して端末へ手動インストールします。

```bash
pnpm run dev:android:device
```

EASの完了画面に表示されたURLを実機で開いてAPKをインストールし、インストール後に次の共通手順へ進みます。

### iOSシミュレータ

シミュレータを起動した状態で実行します。起動中のシミュレータを優先して自動判定します。

```bash
pnpm run dev:ios:simulator
```

複数のシミュレータが起動している場合は、候補に表示されたUDIDを指定します。

```bash
pnpm run dev:ios:simulator -- <UDID>
```

### iOS実機

Appleの署名・端末登録が済んでいる環境で、EAS Development Buildを作成します。

```bash
pnpm run dev:ios:device
```

EASの完了画面に表示されたURLから実機へインストールし、インストール後に次の共通手順へ進みます。

### 共通: Metroへ接続

Development Buildを端末・シミュレータへインストールした後、プロジェクトのルートでMetroを起動します。

```bash
pnpm run dev
```

表示されたQRを、Expo Goではなくインストール済みの「ふわっと。」Development Buildで開きます。

Expo Goで確認したい場合は、development build用QRではなくExpo Goモードで起動します。

```bash
pnpm run start:expo-go
```

Expo Goで `Something went wrong. Sorry about that. You can go back to Expo home or try to reload the project.` が表示される場合は、development build用QRをExpo Goで開いていないか確認してください。

- [ ] アプリをインストール後、タップして起動できる

- [ ] 当日・終日通知のタイトルが「今日｜『タイトル』」、本文が「今日の予定をお知らせします。」であり、通知時刻が開始時刻として表示されない
- [ ] Android / iOS 実機のロック画面・バナー・通知一覧で、長い予定名（40文字）と OS の大きい文字設定でも用件・いつの予定か・役割が読み取れる
- [ ] 通知を短時間見ただけで、通知を開かずに「用件」「いつの予定か」「準備のためか、当日の知らせか」を説明できる
- [ ] ウォーム起動（フォアグラウンド／バックグラウンド）でリマインダー通知（前日通知・当日通知、過ぎた予定を含む）をタップするとホームへ遷移し、該当リマインダーの詳細シートが直接開く

- [ ] Android: 端末の「リマインダー」通知チャンネルで音をOFFにすると、既存・新規リマインダーが無音になる
- [ ] Android: 端末の「リマインダー」通知チャンネルで音をONに戻すと、既存・新規リマインダーが鳴る

- [ ] 通知権限がない状態で追加すると、リマインダーは保存され「通知を予約できませんでした」と表示される
- [ ] 上記の警告から設定画面へ移動し、必要な権限を許可して戻ると未予約のリマインダーが再予約される
- [ ] Android 12以降で現在時刻の1分後を指定し、アプリをバックグラウンドにして、指定時刻から最大60分程度の遅延を許容して通知が届く
- [ ] Android 12以降で現在時刻の1分後を指定し、アプリを終了して、指定時刻から最大60分程度の遅延を許容して通知が届く
- [ ] iOSで現在時刻の1分後を指定し、アプリをバックグラウンドにしても指定時刻に通知が届く

**期待される結果**

- `expo-notifications` の `scheduleNotificationAsync` で予約された通知が、実機で期待されるタイミングで届く
- 通知応答は `src/lib/notifications/` 内の公開ラッパーで購読して `data.reminderId` を読み取り、Widget の `action=view&id=...` ディープリンク処理と共通化した経路で該当リマインダー詳細（削除済みの場合は 1 回限りの案内）へ遷移する
- iOS: `DATE` トリガーが指定時刻付近に動作する
- Android 12以降: `SCHEDULE_EXACT_ALARM` を使わない `DATE` トリガーは inexact alarm として扱われるため、バックグラウンド／アプリ終了時は指定時刻から最大60分程度の遅延を許容する。遅延した場合は実測時刻と端末のDoze・バッテリー最適化設定を記録する
- Android: `TIME_INTERVAL` / `DATE` トリガーが通知権限の許可状態に応じて動作する
- Android: `reminder-alerts-high`（`AndroidImportance.HIGH` / `AndroidNotificationPriority.HIGH`）により前日・当日通知が heads-up バナーとして表示され、旧チャンネル（`reminder-silent` / `reminder-alerts`）の予約通知も起動時に移行・削除される
- Android: 音とバイブレーションの変更が「リマインダー」チャンネルのOS設定に従って既存・新規通知へ反映される
- 予約失敗を成功表示せず、権限回復後はIDがない当日通知・未来の前日通知が個別に再予約され、共通設定と異なる前日時刻も修復される

### Android Widget（Development Build）

Android Widget は Expo Go では確認せず、Widget 対応済みの Development Build をホーム画面へ追加して確認する。先頭の予定を大きな「次のリマインド」、残りをキューとして表示し、下端に横幅いっぱいの「追加する」を固定する。アプリで選択中のsky・lavender・mintテーマを不透明な読み取り面・細いガラスの縁・追加ボタンへ反映する。装飾泡は小さな静止画像とし、壁紙のリアルタイムぼかしは行わない。時間帯別の背景画像やランダム配置は使用しない。AndroidのRemoteViewsは任意の連続アニメーションを実行できず、`updatePeriodMillis` の下限も30分のため、アプリ終了中の期限切れ除外はbest-effortとして扱う。
